## 验证的真实流程

- 手机五项导航、顶部滚动模糊、项目四个栏目、维护项目仍公开、截图预览/Escape/焦点返回。
- 管理员真实登录、发布项目、编辑关联开发计划、拒绝未授权与跨源改写。
- 保存前离开提醒、手机品牌导航保护、浏览器历史导航后的临时草稿恢复。
- 工具开关影响目录、路由及 Sitemap；关闭全部可选模块后 Core/后台/health/SEO 仍可用，重新开启后数据保留。
- 密码、Unicode Base64、JSON 异常输入、IP 本地分类、时间戳、安全 Markdown 预览；真实浏览器输入没有被 POST 上传。
- 真实图片上传与固定 WebP 响应；虚假图片、超限 JSON、危险 URL 和不支持字段被拒绝。
- 旧 v0 库的内容和资料保留，升级前有原始快照；高版本库在任何 DDL 前拒绝。
- WAL 内容进入一致备份；媒体及清单校验；真实备份下载；新目录恢复；损坏备份和已有目标被拒绝。
- 失败备份仅清理本次生成的临时目录，已有有效备份保留；异常清单不能污染有效历史。
- 未来/过期公告在限制条数前过滤；删除已发布记录更新正文时间；动态深链接展开正确面板。

## 实施决定

- 按用户给定的 V4.4 设计和持续开发指令直接实现；工作发生在当前目录的独立开发分支，保留 main 和本机旧资料。若改用 worktree，属于工作区调整，不影响已实现代码。
- 正式内容保存在 SQLite；当前标签页的 sessionStorage 仅恢复未保存草稿，成功保存后清除，且不作为公开或跨设备的数据源。缓存不可用时提示先保存，关闭标签页不提供跨设备恢复。
- 关闭“最近动态”保留详情中的历史，关闭“游戏展示”保留项目分类中的游戏；这符合展示模块和内容权威分开的范围。如果需要整类隐藏，可再调整模块规则。
- 基础原型工具经验证进入 P1；Word、HTML → Markdown、外部 IP 归属地、统一用户及外部数据继续按后续阶段处理，不用演示数据补空缺。
- 首轮测试曾因导入顺序产生一份仅含已知测试内容的默认目录数据库；已确认内容并完整保留到忽略的 .tmp，未删除。之后测试全用隔离目录。
- pnpm 11.25.0 要求 Node >=22.13，项目最低版本与文档已对齐；实际本地验证为 Node 24.19.0。
