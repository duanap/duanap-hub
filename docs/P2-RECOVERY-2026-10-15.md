# P2 隔离备份、插件组合和恢复验收

本批完成默认关闭候选的进一步验收，没有安装生产 Provider/Bridge，没有改生产缓存、应用凭据或账号/积分。主域与博客 QQ 应用仍独立且均在审核中，真实授权另行验收。

## WordPress 一致备份恢复

实际 MariaDB、WordPress 7.1.3、完整子比 9.0、Provider 4.5.2 与 Bridge 0.3.0。源为已标记的独立合成库，HTTP 停止；不读取或复制生产用户数据库。对全部 InnoDB 表使用 `mariadb-dump --single-transaction`，维护期间禁止 DDL 和文件写入，文件与 SQL 归档留在服务器私有目录。

- 9 项文件/服务边界及 4 项启动前配置测试：未标记目录、原目录/已有目标、非隔离库名、符号链接及路径穿越被拒绝，SQL/文件篡改会被完整性检查拒绝。目录内指向其他归档目录的符号链接同样拒绝。两个测试服务或 1030 端口仍在运行时拒绝改配置；加载 WordPress 前静态核对合成库名/账号、本机 Unix socket、开发标记、回环站点及禁止外部 HTTP/计划任务的常量。
- 19 项实际恢复检查：23 张表与 6 张 Provider 私有表，以及 WordPress/主题/插件/夹具文件恢复到全新库和目录，启动前逐表比较行与建表结构摘要，文件逐一校验。恢复目标使用全新数据库账号，源库不被覆盖。
- 原 UID、第三方唯一绑定、原生积分/流水/累计天数、每日事件及回执保持一致；恢复后同日重试返回原回执，只发一次奖励。备份后追加的源库写入保留在源库，恢复副本不包含这条较晚写入，整个演练不回写源库。
- 恢复副本首次启动会新增依赖目录路径的 WordPress 主题缓存项。因此在首次启动前检查整库原始一致，启动后独立检查业务不变量；不通过忽略身份或积分差异来放宽检查。

这是恢复方法与数据覆盖范围的隔离证据，**不是生产备份已演练完成**。真实上线前仍需为最终启用的主题/插件/缓存组合生成受控一致备份，验证版本、私有配置及媒体；生产用户数据库不得复制进开发仓库。备份含 Provider 私有凭据/令牌及 WordPress 会话，需要严格权限；生产灾难恢复后在重新开放前撤销旧会话/授权并对账。禁止把旧积分快照覆盖到仍在发生新交易的生产库。

## WPOPT 组合

只读审查已安装的 WPOPT 2.5.8，未发现额外 `user_checkined` 奖励回调；其可选登录设备限制会写原生会话元数据，REST、邮件、查询缓存等选项也可能影响集成，不能仅凭“优化插件”推定无影响。

从生产只读取 11 个白名单普通布尔/数字开关，在恢复副本内启用私下复制的完整插件代码，不复制 SMTP、Redis、AI 等服务密钥或真实账号。此组合下，签到 24、社交绑定 25、截获邮件的密码恢复 18 项通过。生产其他配置和未来改动不在这份证据范围内；生产 Redis 组合尚未开放写入。

同一组合继续通过实际 HTTP 本人读取 66、OAuth 33、社交绑定 27、原生/API 混合签到 13 项，共 139 项。测试服务仅监听回环、阻断非回环外连并设置资源上限，结束后停止；授权传输使用合成外部响应。复用的读取夹具原有签到日期会随自然日过期，现每轮只刷新明确标记的合成 Alice 日期，不修改产品日期判断或生产账号。

## 密码恢复

合成社交账号使用 `example.invalid` 邮箱，邮件在 `pre_wp_mail` 被截获，不发送给任何人。18 项检查覆盖真实 WordPress 重置链接、错误/过期/被替换/已使用的 key 拒绝、密码更新、旧 Cookie 失效、重新认证后才记录密码备用登录、原 UID/绑定和已提交积分/流水/回执不变。重置 key、邮件正文、密码与 Cookie 不进入日志或 Git。

这证明核心恢复流程可运行，**不证明真实邮箱已验证或邮件已送达**。实际收件邮箱、SMTP/邮件服务、垃圾邮件投递、纯社交用户的邮箱绑定和恢复体验仍需后续独立验收；本批不发送真实邮件。

## Redis 的准确边界

用已安装 Redis Object Cache 的代码和独立 Redis 进程，通过临时 Unix socket、独立前缀连接，TCP 端口为 0；不连接、清空或读取生产 Redis。18 项检查包含连接/拒绝写入/回执查询，以及一个事务缓存风险反例：标准 WordPress 元数据写入后在事务内读取，会把未提交积分放入 Redis；第二个 PHP 进程能读到该临时值，而 SQL 仍是旧值。SQL 回滚本身不能回滚 Redis 值，定向失效后才恢复一致。测试最终核对业务元数据未变，并停止独立进程、移除测试 drop-in、恢复夹具配置。

这是实际缓存下的保护和风险复现，**不是 Redis 并发签到兼容已通过**。当前明确不满足开放写入条件；需要先设计事务内缓存隔离与提交后失效/故障处理，再证明并发、提交、回滚和跨用户数据一致。不能直接删除 `wp_using_ext_object_cache()` 保护或以一次 SQL 回滚成功推断缓存安全。

## 复现

测试脚本在 `integrations/wordpress/duanap-hub-bridge/tests/`。仅在服务器受控私有路径运行，要求 `isolated` 标记、开发环境、合成 `hub_p2_audit_<hex>` 数据库与回环站点；恢复演练还要求源 HTTP 已停止，不支持覆盖现有目标或生产数据库。

先将本目录的 `fixture-isolation.php` 原样安装为隔离站 `wp-content/mu-plugins/000-duanap-test-isolation.php`，不要安装到生产。启动前校验会比较文件摘要，确保真实邮件与外部 HTTP 在插件加载前已被拦截；未安装、文件改变或配置不是受支持的字面量形式时直接拒绝执行，不猜测配置或先尝试连接。PHP 帮助程序不作为生产运维入口。

```sh
python3 recovery-support-test.py
python3 recovery-bootstrap-test.py --php PHP_BINARY
python3 recovery.py --wp-root ISOLATED_WORDPRESS_ROOT --php PHP_BINARY
# Use the NEW restored root from the preceding private recovery report.
python3 wpopt.py --wp-root RESTORED_ROOT --php PHP_BINARY \
  --plugin-source INSTALLED_WPOPT_CODE --safe-flags PRIVATE_ALLOWLISTED_FLAGS_JSON
python3 wpopt-http.py --wp-root RESTORED_ROOT --php PHP_BINARY --config PRIVATE_SYNTHETIC_CONFIG
php password-recovery.php RESTORED_ROOT
python3 cache.py --wp-root RESTORED_ROOT --php PHP_BINARY \
  --redis-plugin-source INSTALLED_REDIS_PLUGIN_CODE
```

每次 WPOPT/Redis 组合演练使用未安装对应插件的新恢复副本。源数据库凭据只在内存和 0600 私有客户端配置中使用，不作为进程参数或公开输出。失败归档和新库保留供诊断，不自动删除数据库或恢复旧生产快照。

本地公开主站/Studio/Markdown/QQ 入口回归 42 项、恢复 7 项与管理员环境 1 项通过；两个需要显式开启 QQ 的条件用例按配置跳过，本批不改变其实现。PHP 原有重复 mbstring 加载警告仍存在，未在本批修改运行环境。
