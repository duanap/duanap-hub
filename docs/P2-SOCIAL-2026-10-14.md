# P2-3 账号绑定与恢复隔离验收

状态：隔离候选完成，生产未启用。延续免费 OAuth2 + S256 PKCE + Bridge 方案；WordPress 管理用户与绑定，Studio 鉴权独立。新增主站 `/account/bindings` 和本人只读 API；绑定、解绑及密码恢复进入博客权威流程。

## 修改范围

- `components/BindingCenter.tsx`、账号页面/API 和 `lib/accounts`：本人身份一致性、DTO 白名单、管理链接同源检查与 UID 核对，移动端展示。主站没有社交账号或密码写入接口。
- Bridge 0.2.0 的 `social-bindings.php`、`social-routes.php`、身份事务 helper 和钩子：唯一映射、近期验证、原生 SDK/路由复用、最后登录方式及安全恢复入口。
- 社交 HTTP/数据库测试、主站绑定测试，以及测试夹具的显式回环地址和只输出汇总的并发所有权检查。

三种平台适配均默认关闭。`DUANAP_HUB_SOCIAL_ENABLED=true` 是独立开关，不随 Hub accounts 模块自动开启。应用 ID/密钥继续只在 WordPress 私有配置；主题必须启用对应平台、直接授权模式、准确 HTTPS 回调，并安装支持的 SDK。完整配置和回退步骤见 [Bridge README](../integrations/wordpress/duanap-hub-bridge/README.md)。

## 独立审查修正

1. 历史 claim 与原生 metadata 不一致时拒绝登录，防止关闭适配期间原生解绑后，重新启用恢复已撤销身份。另核对 subject 的唯一原生所有者。
2. 备用平台判定复用登录配置检查；错误回调或缺 SDK 的平台不能允许解绑唯一登录方式。
3. 事务内直接 SQL 核对 metadata，避免读取提交前共享缓存；提交/回滚后统一清理 WP 与主题缓存。测试注入提交前旧缓存验证结果，但不将此视为真实 Redis 验收。

## 验证与边界

所有 WordPress 测试均在全新数据库与合成用户下进行，没有复制生产用户、余额或商业源码进入仓库。私有完整子比 9.0、WordPress 7.1.3、PHP 8.4.26、MariaDB 10.11、Provider 4.5.2、Yurun OAuth Login 2.1.0 / YurunHTTP 3.5.3 用于隔离验证。

- 社交数据库：25 项断言，含不合并同昵称、旧 claim 撤销、冲突、近期验证、最后方式、配置失效、缓存交错、SQL 写入失败无孤儿用户。
- 完整主题与原装 SDK 的社交 HTTP：27 项，含三平台进入同一 UID、实际回调路径、随机 state、浏览器隔离、单次消费、nonce、真实本人绑定 API、解绑保护及八路首次授权仅产生一个用户映射。外部平台 HTTP 使用私有合成响应；没有真实 QQ/GitHub/Gitee 授权证明。
- 完整主题下既有本人读取 66 项、OAuth 33 项；三轮八路并发兑换均仅一份令牌。
- 主站生产构建、断网运行：账号 26 项、Core 36 项；类型、构建、结构检查通过；备份/恢复 7 项、管理员环境 1 项。移动端绑定页面已目视检查。

生产仍未安装 Provider/Bridge。线上只读检查发现新增 WPOPT 2.5.8，未在本次隔离环境中复制启用；已有 Redis Cache 也未进行持久缓存兼容验收。QQ/GitHub/Gitee 的应用参数仍未配置。正式上线还需要真实平台授权、生产插件组合、HTTPS/缓存、密码及邮件找回、备份和回退演练。

原生密码设置/找回仍依赖博客配置的恢复渠道。自动生成的未知密码不能充当备用登录；无恢复渠道账号须由运营方独立核实。旧绑定缺 AppID 来源时拒绝自动迁移；人工来源核实是独立任务。

本次未部署 P2、未改生产插件或用户数据。隔离 HTTP 服务验收后停止，保留标记明确的私有测试目录供下一阶段使用。下一步为 P2-4：统一签到入口和幂等保护，先审查子比实际签到事务及缓存行为。
