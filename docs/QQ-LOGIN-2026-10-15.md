# 首页 QQ 登录与申请准备

用户最新状态：QQ 互联应用尚未创建，没有 AppID。此前文档中的“已有审核通过应用”已由此更正。首页入口准备应与 P2-5 的 Redis/备份等工作并行，不等待 P2 全部完成才申请。

## 当前实现

- 顶部导航提供官方 16px 图标加“QQ登录”，首页首屏操作区提供腾讯官方 170×32 按钮；原图本地保存，图像/尺寸/颜色不改动，来源见 `public/qq/README.md`。
- 点击统一进入 `/login/qq`。默认未开通，显示明确提示与返回首页，不使用虚假 AppID，不跳转无效腾讯授权链接，不表示已经满足审核。
- 配置 `HUB_QQ_LOGIN_ENABLED=1` 和有效 HTTPS `HUB_WORDPRESS_URL` 后，入口固定跳转该博客安装路径下的 `oauth/qq`，复用原生 SDK、state 和回调；不接受请求参数控制目的地，不在首页发网络探测，不通过预取触发授权。
- 此入口与 Hub accounts/签到开关独立，不安装 WordPress 插件，不创建 Hub 用户会话，也不代表已完成主站 SSO。申请通过后再按用户要求确定入口调整方案。
- 登录说明和跳转响应为 private/no-store/noindex，不加入 Sitemap；公开页面与 Studio 的故障隔离保持原合同。

## 申请顺序

1. 先完成开发者注册和网站应用创建，按控制台要求填写网站信息、备案、图标和回调。官方创建应用文档说明，创建后可在管理中心查看 AppID/AppKey；没有这些参数无法生成本应用的有效授权请求。
2. 获得应用参数后，将 AppID/AppKey 填到博客私有配置，设置准确回调。AppKey 不放 Git、浏览器、主站公开设置或聊天中。
3. 校验原生 QQ 登录端到端，再开启首页原生跳转开关。QQ 回调归博客；不要把主站用于 WordPress OAuth2 的 `/api/auth/callback` 误当成 QQ 回调。具体登记地址以博客原生配置和 QQ 控制台校验为准。
4. 按控制台流程提交/补充审核。首页应能找到官方入口，点击能进入本应用真实授权并完成博客登录；仅放按钮、只显示未开通或只跳腾讯首页不算完整接入。
5. 通过审核后再确定主站统一会话/登录入口的最终方案。积分签到、Redis、WPOPT、恢复等仍按 P2-5 独立验收，不能因按钮可跳授权就全部开启。

## 官方依据（2026-10-15 核实）

- [创建应用](https://wiki.connect.qq.com/__trashed-2)：先申请应用取得凭据，创建后可查看 AppID/AppKey。
- [授权请求参数](https://wiki.connect.qq.com/%E4%BD%BF%E7%94%A8authorization_code%E8%8E%B7%E5%8F%96access_token)：`client_id`、准确回调和浏览器绑定 state 是必需参数。
- [审核规范](https://wiki.connect.qq.com/%E7%BD%91%E7%AB%99%E5%AE%A1%E6%A0%B8%E8%A7%84%E8%8C%83)：主要页面缺入口、登录或授权失败都可能导致驳回。
- [按钮放置和官方资源](https://wiki.connect.qq.com/%E6%94%BE%E7%BD%AEqq%E7%99%BB%E5%BD%95%E6%8C%89%E9%92%AE_oauth2-0)：使用官方素材，并保持容易查找。

文档不保证审核通过或未审核应用的开放范围；实际控制台状态与平台校验为准。当前没有真实 AppID，真实授权和审核仍未验证。
