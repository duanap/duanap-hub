# P1 主站完善实施计划

用户已要求依次完成并持续推进。范围以 ROADMAP-V1.1、REQUIREMENTS-V1.0 和本次批准的任务清单为准。

## 实施与验收

1. 保存 Studio 基线：12 项浏览器验收后提交并推送开发分支，不合并 main。
2. 媒体与项目：仅接受不超过 5 MiB 的 PNG/JPEG/WebP/GIF 栅格图片；通过文件签名和图像解码校验，存入 HUB_DATA_DIR/media，随机文件名，受保护上传，公开只读媒体路由。项目增加图标、分组、标签、截图、版本日期、排序；公告增加路线图状态；已发布 slug 变化保留重定向。旧数据库仅增加兼容字段，不导入生产数据。
3. 前台与 Studio：后台可编辑首页模块和排序、社交资料；完整展示项目图片与版本内容；侧栏折叠、明暗主题、按需桌面/手机预览；可用性优先，使用现有 React/CSS，不引入大型 UI 框架。
4. 备份恢复：SQLite 在线快照与媒体打包，受保护列表/下载；恢复通过停止应用后的 CLI 执行，校验格式/完整性/路径且先保存回滚快照，避免在运行进程中替换数据库。UI 提供明确的离线恢复流程。测试必须实际恢复独立测试数据。
5. SEO 与模块：动态 robots、OG 图、JSON-LD、canonical、Sitemap/RSS、slug 重定向；验证全部可选模块关闭、草稿和维护状态、恶意输入、权限与 Origin、第三方 API 无依赖。
6. 部署迁移准备：只读比较旧仓库与部署说明，准备测试域名/Nginx 缓存规则、备份/迁移映射与回滚命令。真实生产仓库/路径必须来自实测，禁止猜测导入。实际替换生产需单独决定。

## 边界与风险

- Core 保持 SQLite 单体，不新增 Docker、付费 CI、WordPress/QQ/EdgeOne API 运行依赖。
- 管理员接口先鉴权与 Origin 校验；媒体/备份不进入 Git，不包含环境密钥或管理员会话。
- 恢复为离线操作：安全优于在 Next.js 存活时热替换 SQLite；代价是需要短暂维护窗口。
- 验证用隔离数据库、临时凭据和本地端口；开发完成不等于生产迁移完成。
