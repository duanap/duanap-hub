# duanap Hub P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本轮采用当前会话内直接实施；未请求子代理。

**Goal:** 将 v0.1.0 开发包完善为可在本地独立运行、可操作与可验收的 P1 主站，准备后续独立上线所需的运维能力。

**Architecture:** 延续 Next.js 模块化单体、独立 SQLite、管理员会话及服务端渲染。数据模型做带版本的增量迁移，前台、Studio、SEO 使用同一份公开可见性判定。第三方模块保持未实现/不可启用，Core 不调用其 API。

**Tech Stack:** Next.js 16.2.12、React 19.2.0、TypeScript、better-sqlite3 12.10.0、react-markdown、轻量自定义 CSS；生产 Node.js 22，本机先验证 Node.js 24.19.0。包管理先使用本机可用 pnpm，固定版本并保留锁文件；图像处理按需采用 sharp。

**Spec:** 用户提供的 `duanap Hub · 需求与技术架构 V1.0.md`（重点第 3–7、11、14–15、17 章）及 `duanap-hub-roadmap-v1.1.md` 的 P1 范围；导入时对应 `docs/REQUIREMENTS-V1.0.md`、`docs/ROADMAP-V1.1.md`。检查证据见 `../../DEVKIT-AUDIT-2026-10-10.md`。

## Global Constraints

- 第一阶段主站不得要求 WordPress、QQ、游戏服务、EdgeOne、GitHub API 已配置才能启动。
- 可选模块禁用立即生效；扩展服务维护或超时只影响自己的区域，不连带主站、后台、SEO。
- 「关闭模块」指功能开关、路由展示和 API 适配器停止参与，并非免编译更新任意代码。
- 项目发布状态与手动运营状态分开；维护中保留已发布详情、版本和公告。
- 不对历史数据库进行猜测性迁移；生产数据导入、生产部署和替换旧主站不属于本次本地实施。
- 管理员独立鉴权，改写 API 校验会话、来源和输入；密钥、媒体、数据库及备份不进入 Git。
- 不引入 Docker/K8s、Redis 集群、复杂队列、付费 GitHub 功能或强制 CI。

## Review Focus

1. 配置保存/模块切换后，新请求读取新内容；缓存不能让已关闭模块继续公开。
2. 未保存表单遇到切页、切项目、刷新或保存失败时保留草稿并清楚提示。
3. 草稿、撤回、维护状态和旧 slug 不得泄露内容、污染 Sitemap 或产生无解释死链。
4. 超大或伪造图片、危险协议、越界路径和未授权写入必须被拒绝，错误不暴露内部路径。
5. WAL 开启、备份缺损、恢复目标已有数据时不得静默得到不完整备份或覆盖数据。
