# P2 账号与积分设计草案

日期：2026-10-13。状态：供用户审阅的规划草案；本轮不实现产品代码、不安装博客插件、不修改线上账号或积分。

## 目标与当前起点

目标是让主站和博客使用同一 WordPress 用户、同一积分余额和同一每日签到记录。QQ 为首选登录方式，保留站内账号登录，并支持绑定 GitHub/Gitee。P1 公开内容与 Studio 保持独立可用。

仓库已有 P1，`accounts` 模块仍为 `available=false`；尚无普通用户会话、WordPress 适配器或 Bridge 插件。本轮以现有 ROADMAP-V1.1 为交付顺序，以 REQUIREMENTS-V1.0 第 8、9、12、13 章为需求依据。

用户已确认子比自带 QQ 登录，主站尚未接入。P2 复用博客现有 QQ 登录与账户，不在主站另建一套 QQ 注册流程；已有 QQ 登录不等于已提供跨站授权协议。执行顺序调整为先完成 P1 项目 Markdown 可视化编辑修复与验收，再启动 P2-0。

P1 尚需站长补充实际运营内容和观察搜索平台收录，但这些不是 P2 只读审计与隔离开发的前置依赖。P2 正式启用仍必须通过自身的集成、备份与故障隔离验收。

## 已确定的边界

- WordPress 是账号、第三方绑定、`hub_uid`、积分、签到和流水的权威；主站不建立第二套会员或余额账本。
- Studio 密码与管理员会话独立。即使普通用户在 WordPress 中是管理员，也不会自动成为 Studio 管理员。
- Core 启动及公开页面不请求 WordPress。关闭账号模块、未配置身份服务或博客故障，均不能影响首页、项目、工具、后台、Sitemap/RSS。
- P2 完成主站/博客账号和签到；QQ Bot、游戏认领、文章同步、奖励发放接口属于 P3。
- 不直接修改子比商业主题源码，不从 Hub 直接写 WordPress 表，不提交真实用户数据、第三方密钥或私有源码。
- 不强制购买身份插件，不新增 Docker、微服务或独立认证域名。需要改动这一边界时另行说明方案。

## 技术路线与选择门槛

2026-10-14 只读审计后，用户选择优先验证免费 OAuth2 + PKCE + 自有 `duanap-hub-bridge`，保持现有部署结构。候选为 WP OAuth Server 4.5.2 社区包；版本、许可和组件证据见 `docs/P2-COMPATIBILITY.md`，完整兼容尚未通过。QQ/站内账号登录在博客端完成，Hub 使用授权码 + S256，通过服务器交换不透明访问令牌，并由受保护的 WordPress 本人 API 确认身份，建立自己的独立会话。

原优先 OIDC 草案不再作为首选：免费候选未满足全部门槛，另一个候选将 OIDC/刷新列为 Pro。本路线不接收或信任未提供的 ID Token，不将浏览器自报身份或 WordPress Cookie 当作授权凭据；全部身份和权限仍由服务器验证访问令牌、客户端与本人 API。具体插件仅在完整授权、重放、撤销和主题兼容实测通过后冻结。

备选路线是在 WordPress 身份权威不变的前提下评估独立的成熟授权服务。它增加部署和维护成本，仅在 WordPress Provider 无法满足要求时提出新的架构决策。本计划不默认采用，也不自写 OIDC 授权服务器。

以下情况不得以弱化方案继续：Provider 不支持所需授权码/S256、无法验证访问令牌/客户端/用户、子比登录冲突或无法处理撤销。若未来采用 OIDC，再要求签名/issuer/audience/JWKS 校验；不透明 OAuth2 令牌必须由权威资源端校验，不能自行解析成身份。不能以共享整个父域 Cookie、裸传 OpenID、通用管理员 Application Password 或收集 WordPress 密码替代用户授权。

### 首批必须实际核实

1. 已安装 WordPress/PHP/子比版本，相关登录插件及主题扩展点；历史笔记和公开教程只用于定位。
2. QQ/GitHub/Gitee 是否启用、应用和回调是否可用，现有绑定的稳定 subject 与保存方式；不输出密钥或用户标识样本。
3. 子比首次登录建号、绑定/解绑、账户恢复及原生签到入口的实际调用路径。
4. 积分余额、流水、连续签到、奖励计算和缓存更新的实际接口、事务参与表与数据库引擎。
5. OAuth2 Provider 的授权码、强制 S256、state、精确回调、本人资源授权、授权码一次消费、令牌期限/撤销与子比登录共存。核实原生与 Provider 共享的 `/oauth/*` 和查询变量，避免覆盖 QQ 回调；独立授权路径优先。若未来采用 OIDC，另验证 nonce/签名/issuer/audience/JWKS。

产出脱敏兼容矩阵和可重复的隔离验证。具体私有源码位置及生产配置仅保存在受控私有记录中。审计未通过时可以继续接口模拟与 UI 验证，但不能启用真实账号/积分写入。

## 身份与会话设计

WordPress 插件为用户维护不可重用的随机 `hub_uid`，对 WP 用户 ID 和 UID 分别建立唯一约束。已有用户按认证访问或受控批次补齐，不重建原账户。

第三方身份唯一键包含 `provider + app_id + subject`。复用现有身份前必须核对真实来源；同昵称、头像或未验证邮箱不合并。绑定要求已登录及近期重新认证，冲突拒绝覆盖；解绑最后一种可用登录方式必须拒绝。失去 QQ 访问权时走已验证的备用登录或博客账户恢复流程。

浏览器进入博客登录/授权页，授权回到 Hub 后由服务器校验并换取凭据。每个站点使用自己的 Cookie，不共享 WordPress Cookie。Hub 普通用户 Cookie 为 `hub_user_session`，生产设置 HttpOnly、Secure、SameSite=Lax、Path=/，不设置 Domain；和 `hub_admin_session` 完全分离。

Hub 仅在受控持久化目录中新增独立 `accounts.sqlite`，存放会话哈希、一次性授权事务、服务器端加密令牌和必要私有缓存；不存 WordPress 密码，不作为账号或积分权威。独立文件使 P1 内容数据库模式不变，便于停用/回退账号功能。沿用现有单进程数据目录约束。身份库使用短事务；调用 WordPress 或刷新令牌时不得占用 Core 的内容写入/备份队列。外部调用必须有超时，写入结果未知时不自动重试。

授权事务有效期 5 分钟、只消费一次；会话不能超过上游访问令牌有效期。免费候选源码默认访问令牌 3600 秒，完整实测前不承诺 7 天或刷新令牌；过期后重新进入博客授权。每次请求检查本地过期状态，已确认撤销时清除对应会话。Provider 的撤销传播方式和实际有效窗口由首批审计确定，不承诺没有证据的实时全站登出。

令牌加密使用服务器端独立密钥，浏览器只持有随机会话 Cookie。访问令牌只用于权威本人资源 API；免费路线不使用 ID Token 或刷新令牌。重新授权事务使用独立 state/PKCE；若以后增加经验证的刷新能力，再实现单次执行与原子更新。

授权事务、过期会话和私有缓存须按用途设置保留期限并清理，日志对身份和凭据脱敏。用户中心提供必要的隐私说明与退出/撤销入口；博客账户删除及积分审计记录的保留按博客已确认的账户管理规则处理，Hub 不另行删除权威记录。

## 用户中心与接口边界

主站提供 `/account`、积分/签到、绑定和会话页面；头像、昵称、UID、余额、状态与流水来自 WordPress。资料编辑和密码恢复优先进入博客现有流程。游戏角色/战绩暂不展示伪数据。

以下是拟定业务接口，Provider 的 authorize/token/revoke 地址必须由完整隔离验证确定；免费 OAuth2 路线不依赖 OIDC discovery：

| Hub 内部入口 | Bridge 本人接口 |
| --- | --- |
| `/api/auth/login`、`/api/auth/callback`、`/api/auth/logout` | 经验证的 Provider 授权/撤销流程 |
| `GET /api/account/me` | `GET /wp-json/duanap-hub/v1/me` |
| `GET /api/account/points` | `GET /wp-json/duanap-hub/v1/me/points` |
| `GET/POST /api/account/checkin` | `GET/POST /wp-json/duanap-hub/v1/me/checkin` |
| `GET /api/account/points/history` | `GET /wp-json/duanap-hub/v1/me/points/history` |
| `/api/account/bindings/*` | 经认证的本人绑定/解绑流程；具体第三方回调由审计冻结 |
| `/api/account/sessions/*` | Hub 本人会话管理；上游撤销能力按 Provider 合同实现 |

接口不接受客户端自报的用户身份作为授权依据。Bridge 的 `hub_uid` 在服务端校验后映射为内部 `hubUid`。退出、签到、绑定/解绑、会话撤销使用改写请求并校验来源与 CSRF；OAuth2 回调使用一次性 state、PKCE 与精确回调校验。401 未认证、403 无权限、409 绑定/业务冲突、429 限流、503 上游不可用；签到结果未知时提供查询状态，不显示到账成功。

账号、回调与接口响应为 `private, no-store`，不进入 Sitemap/RSS；真实鉴权优先于 robots。OAuth 回跳目标限定站内路径，禁止开放跳转。新增回调与账号路径上线前必须检查 Nginx/EdgeOne/WAF。

## 积分与签到一致性

签到日由 WordPress 服务端按 `Asia/Shanghai` 计算，时间保存 UTC。唯一业务约束为 `hub_uid + event_type + business_date`；请求 ID 不能代替全站每日唯一判定。QQ Bot 将来接同一服务，此阶段不开放 Bot 写入。

博客原生按钮与 Bridge API 必须进入同一判定和发奖路径。优先使用已核实的主题扩展点，通过插件接入；不能仅保护 API 而让原生博客按钮仍独立发奖。

只有确认积分更新、原生签到状态和 Bridge 事件结果能在同一数据库事务内完成，且缓存行为一致时，才按原子事务方案实现。否则必须另写可证明不会重复发奖的处理/对账设计并验证；这一批暂停正式写入，不擅自宣称 exactly-once。

执行结果区分成功、已签到、处理中和失败。网络超时后先查询同一业务结果，不能盲目重试积分修改。前端刷新权威余额，不自行叠加奖励。业务事件保留来源、结果和审计信息，不记录令牌或密码。

## 故障与恢复

积分读取可使用按用户隔离、标注更新时间的短期缓存；另一用户不能命中该缓存。博客不可用时拒绝新增签到写入，用户中心显示依赖不可用，Core 与 Studio 正常。

Hub 内容备份不打包会员会话、OAuth 事务、令牌或私有缓存；恢复/回退时清除本地普通用户会话，强制重新认证，并按 Provider 能力处理撤销。停机恢复须关闭身份库连接，清理该库及其 WAL/SHM，不仅替换内容库；测试覆盖恢复前凭据不能再次使用。WordPress 用户映射/业务事件的备份归博客运维，不能用旧业务快照覆盖上线后新发生的积分交易。

插件停用或账号模块关闭，不删除用户、映射或事件记录。身份库损坏只使账号功能不可用，不阻断 P1。阶段发布默认关闭账号功能，完整验收后启用；出现问题先关闭功能，保留权威账本和证据。

## 最终验收

- QQ 首次与并发/重复授权只对应一个 WordPress 用户和一个 UID；已绑定平台登录进入同一账户。
- 绑定冲突、跨用户查询、伪造 UID、最后登录方式解绑和普通用户进入 Studio 均被拒绝。
- 主站/博客并发签到、原生按钮 + API、超时后重试及北京时间跨日测试均不重复发奖；余额/流水一致。
- 无配置、模块关闭、WordPress 超时/停机、身份库损坏时，P1 页面、Studio、SEO 仍可用。
- 备份恢复、关闭功能与版本回退有隔离演练证据，私有响应不被 CDN/浏览器公共缓存。
