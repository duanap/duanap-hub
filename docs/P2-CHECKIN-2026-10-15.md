# P2-4 统一签到隔离验收

状态：隔离候选已实现，生产未发布。Bridge 0.3.0 让子比原生 AJAX 按钮与本人 API 共用一个每日事件、用户锁和事务。WordPress 仍是积分/经验/签到与流水权威，主站不建立余额账本。

## 修改与行为

- Bridge `includes/checkin.php`、`events.php` 和入口钩子：独立默认关闭开关、北京时间自然日、稳定 UUID 回执、每日唯一事件、可信入口来源、原生业务逻辑与 SQL 写入保护。
- `assets/checkin.js`：给原生按钮补 nonce，原有主题源码及 AJAX 保持复用；处理中不会把按钮切成已签到。
- Hub `lib/accounts/checkin.ts`、签到 POST/结果 GET、账号界面：本人授权、Origin/CSRF、参数边界、实际结果 DTO；超时明确显示未确认并提供查询，不自动重复写入。
- 测试覆盖数据库失败、首次字段创建、混合入口并发、响应丢失、缓存/写入关闭、连续奖励及跨日。配置、接口与复现命令见 [Bridge README](../integrations/wordpress/duanap-hub-bridge/README.md)。

WordPress 配置 `DUANAP_HUB_CHECKIN_ENABLED=true` 与 Hub 配置 `HUB_CHECKIN_ENABLED=1` 是独立写入门槛，默认均关闭。主题/时区、InnoDB/mysqli、业务钩子必须符合已验收合同；持久对象缓存当前拒绝写入。账号功能本身关闭后仍停止所有账号接口；单独关闭写入保留已授权回执查询。

## 关键修正

独立审查发现关闭写入会同时阻断结果查询，已补失败回归并拆分读写检查；待确认操作的查询按钮不依赖写入开关。入口来源由服务端保存；首次积分字段创建、连续奖励、中断重置和真实跨日执行均补充了测试。

额外数据库断连测试实测发现 WordPress 自动重连会重试原 SQL，可能脱离事务写积分。现对受支持的业务 SQL 添加 `@@in_transaction` 条件，并核对提交连接；断连不会提交无回执的奖励。模拟 COMMIT 已完成但连接丢失时返回未确认，结果查询/重试仍读取同一已提交回执，只发一次奖励。

原生日上限可使签到成功但实际积分到账 0；API 返回差额，避免把期望奖励视为实际发奖。已有原生签到不追发，只登记观测事件。重试返回最初回执及当时余额，当前余额须由本人积分接口重新读取。

## 生产门槛与回退

生产尚未安装 Provider/Bridge，账号及签到均未开启。真实平台授权、Redis 持久对象缓存、WPOPT 插件组合、密码/邮件恢复、私有边缘缓存及 WordPress 一致性备份回退仍待 P2-5 验收。P2-4 隔离证据不代替正式上线条件。

故障收敛先关闭 Hub 写入；必要时关闭 WordPress 统一写入，但关闭该开关会恢复原生主题处理，其并发保证不再由 Bridge 提供。不要把“关闭统一签到”当作全站禁止发奖；如需冻结全部签到，需另行关闭博客原生签到开关。保留事件和 UID/社交映射，通过只读结果确认未决请求。回退代码不删除用户、积分、回执；不能用旧数据库快照覆盖回退期间的新交易。

隔离 HTTP 服务已停止；私有标记目录保留。下一步为 P2-5：联调、备份/停用演练、生产插件组合与受限用户启用条件核对。
