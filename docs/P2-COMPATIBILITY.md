## 原生流程与适配结论

### QQ 与绑定

原生 QQ 回调验证 Session 中的 state，由服务器获取 QQ 用户信息，再查找 WordPress 用户并登录。当前绑定查找使用平台名称与 OpenID 的用户元数据；未找到时按主题配置创建账户或进入绑定选择页。回跳经安全重定向处理，SSO 应继续使用博客已有账号。

这一查找/创建路径未给出数据库级第三方身份唯一保证，也未在绑定键中保存应用维度。Bridge 必须对同一应用/平台/subject 建立唯一约束，并覆盖原生创建与绑定路径；只在 Hub 建映射无法保证并发首次 QQ 登录不会重复注册。存在绑定冲突拒绝逻辑，但重新认证、最后登录方式保护和升级兼容仍需隔离测试。

原生解绑入口已验证 nonce 和本人 ID，但该处理函数内未发现最后登录方式保护或近期重新认证判定，需要 Bridge 兼容策略覆盖，不能只保护主站解绑按钮。

### 签到与积分

已确认原生 AJAX 签到调用 `zib_user_checkin`，更新签到详情、累计/连续天数后触发 `user_checkined`，积分回调进入主题免费积分及余额更新流程。

原生 AJAX 包含文件锁节流，但锁只保护节流记录，并非覆盖整段签到、发奖和流水事务；不能代替全站每日幂等约束。Bridge 与博客原生按钮须进入同一业务判定，不能只保护新增 API。

积分已有直接 SQL 数值更新与缓存清理，签到详情和积分流水仍经元数据分别更新；目前没有全链路短事务证据。签到详情最多保留 30 条，积分展示流水最多保留 50 条，均不能充当长期业务事件账本。免费积分存在每日上限；签到状态更新和实际发奖可能不同，API 必须返回权威实际结果，不能把预期奖励视为到账。

后续隔离验证需要覆盖：原生/API 并发、首次积分元数据创建、连续奖励、每日上限、事务失败/回执丢失、Redis 缓存失效与回滚。Bridge 事件表属于 WordPress 内业务证据，不在主站建立第二套余额。

WP OAuth Server 官方将 OIDC 与刷新令牌列为 Pro 能力，不能将社区包直接写成完整免费 OIDC。用户已选择优先验证免费 OAuth2：身份由受保护的本人 API 确认，不校验不存在的 ID Token；候选源码访问令牌默认 3600 秒，会话受实际期限约束，上游过期后重新授权。设计与计划已据此调整，候选仍须完成全链路隔离验收才最终选定。

原生 QQ 与候选 Provider 均使用 `/oauth/*` 和 `oauth` 查询变量。路由生成模拟通过，但完整主题加载与实际授权回跳仍未验收；优先设计独立 Bridge 授权路径并委托成熟 Provider，不修改主题或自写 OAuth 协议，不能直接安装后假定共存。

### 独立实例的进一步证据

使用全新 MariaDB 测试库、临时测试账号及只监听回环地址的 WordPress 7.1.3 实例，没有复制生产数据库或上传文件。候选插件只在此实例激活；生产博客插件列表保持原样。

- 18 项协议检查通过：登录、S256 授权与换令牌、错误 verifier、错客户端/回调、state 缺失、plain 降级、隐式授权、顺序重放、HTTP Basic 的有效/缺失 verifier、本人资源读取/敏感字段排除、no-store、令牌期限和撤销。
- 原始包允许缺失 PKCE；隔离保护原型强制 S256/state/精确回调，并检查授权码的 challenge 信息，保护加入后该用例通过。不改变原插件源码。
- 四 PHP worker 下，8 个请求同时兑换一个授权码，修复前有一轮签发 4 个令牌；加入短事务和授权码行锁、委托原库换令牌并在输出前提交后，3 轮均只签发 1 个。源码只有顺序核销不能证明并发安全。
- 以当前安装主题的原始路由生成函数在隔离 WordPress 中模拟，QQ 登录及 QQ/GitHub/Gitee 回调分别保留正确的 provider 和 callback 标志，authorize/token/revoke 路由可识别。该检查只证明路由生成，不证明已完整加载子比或完成实际 QQ 授权。

保护原型现已转为仓库内 `integrations/wordpress/duanap-hub-bridge/` 的 0.1.0 隔离候选，未在生产安装。正式集成套件已覆盖下述行为；原生绑定唯一性和 Redis 缓存一致性仍待后续验证。PHP CLI 观察到已有的重复 mbstring 加载警告，未修改生产 PHP 配置。

组件探测使用内存样本，不启动 WordPress、不连接真实数据库，不证明授权码并发核销、实际客户端权限、主题登录回跳或缓存兼容已经通过。

## P2-1 只读候选验证（2026-10-14）

在用户持续推进授权下完成正式 Bridge 的隔离实现，范围是身份映射与只读业务接口；P2-0 的完整主题/QQ 门槛不因此视为通过。合成主题夹具提供已审计的读取函数，不是完整子比加载。

- 66 项本人读取断言：匿名/其他客户端拒绝、本人隔离、稳定 UID、并行首次分配、删除退役与不存在用户拒绝、积分与流水字段/分页、北京时间签到状态、封禁/过期封禁无写副作用、无效业务数据返回 503、Provider 停用/主题不兼容、撤销及原余额不变。
- 33 项 OAuth 断言：强制 S256/state/精确回调，表单/JSON/大小写 Basic，同名参数冲突拒绝，错误 verifier、隐式/密码 grant 拒绝，令牌 3600 秒且无 ID Token/refresh；3 轮每轮 8 并发请求成功数为 `[1,1,1]`。
- 独立审查发现的请求解析绕过、配置静默退出、非事务表与写入失败误报均已修复。实际故障触发器分别让 token INSERT/code DELETE 失败，返回 503 且事务回滚，移除故障后原授权码可正常重试；验证存储引擎、令牌长度和历史 Hub 客户端归属。
- Hub 代码/数据库模式未变；生产模式离线浏览器/API 35/35，类型、生产构建、结构检查通过。依赖安装因原生预编译下载超时失败，随后按锁文件安装 JS 包，并复用已验收的同版本/同 Node ABI 本机 SQLite 原生模块完成验证；不把失败安装记录当作通过。
- UID 首次分配只写插件技术映射；业务读取不更新用户、余额、签到或流水。WordPress 角色没有任何映射 Studio 权限的代码路径。

接口合同、支持版本、私有配置占位示例、可重复测试命令和备份/停用边界见 [Bridge README](../integrations/wordpress/duanap-hub-bridge/README.md)。P2-2 的普通用户登录、Hub 会话与只读账号中心现已完成隔离候选，生产账号模块仍关闭。
