## 最小迁移策略

1. 在停止旧服务或一致性快照条件下备份旧数据，实际恢复到独立目录。
2. 从只读副本导出公开资料、备案、作品链接和图片，生成待审核的字段映射；不复制旧登录会话、管理员密码、会员或积分。
3. 将公开作品映射为 Hub 草稿：名称→title、在线链接→externalUrl、介绍→summary/body，分组和显示顺序另行核对。链接启用状态不能自动冒充「正常开放」，人工运营状态默认开发中。
4. 图片经 Hub 上传流程校验/转换后获得新 URL；检查 Markdown 中所有旧图片引用。不能直接把旧 SQLite 改名为 hub.sqlite。
5. 对每条历史 URL 生成映射并人工审核：已有项目详情尽量保留 slug；旧跳转链接按实际目标指定永久跳转；文章继续保留在原系统或指向真实原文。禁止全部跳转首页。
6. 隔离站点验收后才制定切换窗口。保留旧版本、旧进程和 Nginx 原配置；失败时恢复上游和旧版本，而不是覆盖原数据库。

Hub 已实现项目 slug 历史别名到最新已发布详情的 308 永久重定向；尚无针对旧站实际 URL 或生产数据的自动导入程序。主域全新数据部署已明确批准并执行；旧内容的转换/导入仍须单独决定。
