# P3 第一批：博客公开摘要与首页卡片

范围为博客文章/分类/封面、首页独立卡片和综合 RSS。主站只缓存公开摘要，原文与 canonical 留在博客；不读取用户接口、登录 Cookie、账号令牌、签到或积分。P2 的真实自动关联与双站签到仍单独验收，本批不接游戏或机器人身份。

## 数据与失败隔离

服务器配置 `HUB_CONTENT_WORDPRESS_URL=https://blog.duanap.cn/`，Studio 启用“博客动态”。数据源只接受服务器配置，管理员表单和公开请求不能指定 URL；正常运行要求 HTTPS，回环 HTTP 仅限显式隔离测试且主站也为回环地址。对接 WordPress 官方 [文章](https://developer.wordpress.org/rest-api/reference/posts/)和[分类](https://developer.wordpress.org/rest-api/reference/categories/)接口。

匿名读取最多 40 篇文章、100 个分类及对应封面元数据。仅接收 publish、摘要未受密码保护且发布时间已到的文章；HTML 转为纯文本，链接仅允许博客同源，封面仅接受该博客 uploads 路径。每次同步共享 3.5 秒超时，每份 JSON 上限 512 KB，不跟随重定向、不转发 Cookie/Authorization；封面失败可显示无图卡片。无数据源或全部扩展关闭时 Core 仍正常。

主站首页 SSR 与 RSS 先读取本地缓存。首页客户端 API 按 15 分钟间隔检查，RSS 在响应后检查，Studio 可手动同步；无常驻轮询、cron 或新服务。失败保留最近成功摘要和时间，公开请求至少等待一分钟才重试；并发同步复用一个任务。模块禁用后首页、公开 API 与 RSS 移除博客内容，在途任务不能越过启停代次更新缓存。

本地 `hub.sqlite` 新增 `content_settings`、`content_cache` 两个独立表，不扩展旧站点设置 JSON，也不改变库版本。旧发布忽略这些表，旧内容备份恢复后新版本按需建立默认表；普通内容备份包含摘要与展示设置，不包含任何额外账号秘密。

## 运营配置

Studio“博客动态”提供标题、说明、展示 1—12 篇、分类筛选、精选置顶、日期顺序、小/中/大卡片以及成功同步时间和失败状态。模块排序沿用现有“模块管理”；分类筛选同样作用于 RSS。未保存离开提醒与提交期间锁定复用 Studio 既有流程。

综合 `/feed.xml` 保留项目更新，追加链接到博客原文的摘要；博客文章不进入主站 Sitemap，不建立本域重复文章页。失效封面隐藏，移动端单列，明暗主题使用现有颜色变量。
