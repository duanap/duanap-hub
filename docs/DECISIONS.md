# 架构决策记录（ADR 精简版）

| 编号 | 决策 | 理由 | 状态 |
| --- | --- | --- | --- |
| ADR-001 | 独立 `duanap-hub` 仓库，不覆盖既有仓库 | 开发和生产隔离 | 确定 |
| ADR-002 | P1/P2/P3 三阶段独立可上线 | 不阻塞主页上线 | 确定 |
| ADR-003 | Stable Core 用 Next.js / TypeScript / SQLite | 复用已验证技术栈，轻量部署 | 确定 |
| ADR-004 | WordPress/子比为账号和积分权威 | 复用既有用户与签到能力 | 产品决策确定，具体接口待审核 |
| ADR-005 | 内置业务模块 + 可选 API 适配器 | 运行时启停、故障隔离，不做插件商城 | 确定 |
| ADR-006 | QQ 优先登录，多身份绑定 `hub_uid` | 统一跨应用身份 | 需求确定，OIDC 待 P2 验证 |
| ADR-007 | 游戏角色与战绩留在游戏服务 | 避免 WordPress 高频负载 | 确定 |
| ADR-008 | 状态/版本/日志由管理员手工维护 | 符合项目运营需求 | 确定 |
| ADR-009 | SEO 首选 `duanap.cn`，博客独立收录 | 品牌入口与内容原创性分离 | 确定 |
| ADR-010 | P1 不部署 Docker、CI、Redis/K8s、PGSQL | 减少复杂度和成本 | 确定 |
| ADR-011 | Studio 管理员与普通用户身份分权 | 业务权限隔离 | 确定 |

待验证：生产主站代码来源；子比签到钩子；WordPress OIDC 提供者；QQ Bot 实际标识；EdgeOne API 权限；各游戏历史数据映射。
